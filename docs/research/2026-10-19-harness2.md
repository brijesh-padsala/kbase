# Harness² adoption — lesson schema, probed refinement, config lint

> **TL;DR:** What 0.4 lifted from [google-research/harness2](https://github.com/google-research/harness2) @ `1cfe254` (Apache-2.0, cloned 2026-10-19): the cue/domain/evidence lesson schema, a Propose–Probe–Compose skill driven by the local retrieval evaluator, and deterministic agent-config checks in the gate and doctor. Concepts and schemas adopted; no code copied.

## What was adopted

- **Lesson entries carry `cue` + `domain`.** Harness²'s experience records key lessons by the *shape of situation* (`cue`) and task domain — retrieval by construction. `learning/lessons-log.md` now defines the same fields, and the gate rejects staged ✅/⚠ entries that name no evidence (❓ open observations stay exempt). The `domain:` tag enables future per-area splits without a format change.
- **`kb-refine` = Propose–Probe–Compose on the KB.** Their task-level loop probes candidate harnesses with real rollouts; the local analog probes candidate edits on a scratch copy of `knowledge/` with `ksearch-eval --root` — deterministic, stdlib-only, no model calls. Canonical procedure: `template/knowledge/practices/skills/kb-refine.md`; installed as a core skill.
- **Agent-config lint.** Their harness validator rejects skills that are silently dropped at load (`name:`/`description:` frontmatter), unshipped script references, and oversized always-on context. The gate now resolves `scripts/*.py` references in note prose against post-commit index state (or the working tree under `--all`), and doctor FAILs on stub frontmatter an agent cannot parse or whose `name:` overrides the directory. Always-on sizing was already covered by doctor's context inventory.
- **Write-boundary tripwires.** `assert_no_grader_verdicts`/`assert_no_leak_paths` refuse contaminated material before it can be served as evidence later. The gate's analog: credential-shaped filenames and content (PEM blocks, AWS/GitHub/Slack/Google keys, JWTs) never enter `knowledge/`, and plan numbers must be unique (their ledger's duplicate-label check — a repeated label means a silent overwrite).
- **Fixture honesty.** A passing eval against the unchanged starter fixture proves nothing about the project; doctor now WARNs while `evals/cases.jsonl` matches the shipped set.
- **Attribution discipline.** Their reflection prompt prefers `confounded` over invented credit, and selection anonymizes deliverables so the artifact is judged apart from its story. kb-refine records `confounded` and labels candidates invariant/domain; kb-review now judges the diff before the narrative.

## What was not adopted

The rollout machinery — benchmark adapters, OpenCode/Codex executors, the R=4k/P=3k budget ledger — needs model credentials and scored tasks, which is disproportionate for a scaffold whose deliverable is a repo layout. The per-task adopted-harness library duplicates what git already gives `knowledge/`. If a project later wants live harness optimization, `knowledge/` is the natural persistence layer for its experience records — that remains an open integration, not implemented here.

## Convergent decisions (no change)

kbase already enforced the counterparts independently: bounded retrieval output ↔ their `always_on_max` cap; link-at-birth ↔ their untriggered-skill check; the librarian subagent ↔ their `sub_agents/` component.

## Open items (not implemented — self-serve integration notes)

- **Harness² as an external optimizer.** For a project that *does* have repeatable, gradable tasks, harness2 can run against a kbase repo rather than being absorbed into the scaffold. The pieces: a `BenchmarkAdapter` over the project's real tasks (the grading signal — tests pass, diff accepted — is the hard part), a `SurfaceSpec` covering `AGENTS.md`, skill stubs, scripts, and `knowledge/` as the mutable harness tree, and an OpenCode/Codex executor for candidate rollouts (this is where model credentials and per-run API spend live). kbase's role stays persistence and hygiene: adopted harness trees and `cue/lesson/evidence/confidence` records land in `knowledge/` — git-versioned, ksearch-indexed, gate-checked — where harness2's per-run library is ephemeral. It is a batch operation invoked occasionally, not a runtime dependency: run it, adopt winners into the repo, turn it off. `kb-refine` remains the zero-cost manual version of the same loop.
